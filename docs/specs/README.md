# Feature Specs

One file per feature that needs a design before implementation starts: the shape of the system,
the types it introduces, where it plugs into the existing layers, and what it deliberately does
not do.

A spec is written before the code and edited as the design changes. Once the feature ships, the
durable description of how it works belongs in [architecture.md](../architecture.md); the spec
stays as the record of what was intended and what was cut.

Name files after the roadmap item they implement, for example `17-in-game-ui.md`, so a spec and
its [roadmap.md](../roadmap.md) entry are easy to pair.

The `plan-roadmap` skill produces this kind of design for the top not-yet-shipped item, or one
named directly. Its output belongs here.

No specs have been migrated into this directory yet. Designs for already-shipped work live in
[MEMORY.md](../../MEMORY.md), read on demand.
